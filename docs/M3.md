# M3: backend rebuild, approval inbox, health, home

Branch `agent/k0ad33/console-m3` off 2fd2dce. Local only, never pushed. $0, loopback only.

- **Approval inbox** (`ConsoleCore/Approvals.swift`): reads JEV's `~/.config/m3ta/jev/pending/<hash>.json`.
  Approve = Touch ID (LocalAuthentication, biometrics only) then `jev-approve <hash>` (Secure Enclave signature,
  its own Touch ID/password prompt). Decision appended to `~/Library/Application Support/M3taOSConsole/decisions.jsonl`.
  Deny is final: no signature is ever made, approve/run refuse afterwards.
- **Exactly once** (`JEVGate.swift`): console-owned actions run only via `ActionRunner`: ledger says approved
  + jevd (`/var/run/m3ta-jev/jevd.sock`, override `REA_JEV_SOCK`) consumes the single-use signed approval.
  `executed` is written before the side effect. JEV unreachable -> blocked, nothing runs (fail closed).
  Agent-held actions: approving signs once; the agent's unchanged retry is consumed once by jevd.
- **Health** (`Health.swift`): one check across JARVIS 9782/9783, Waypoint 3000, jevd, Ollama, ChatGPT relay,
  OpenBot, Vault MCP, Ether inbox, console backend. GETs/launchd reads only. Restart only for own
  `com.m3ta.* / os.m3ta.* / com.th3m3taway.*` agents minus jarvis/waypoint/paperclip/tailscale/screenpipe/jev,
  and only as an approved inbox action (`launchctl kickstart -k`). Log: `~/Library/Logs/M3taOSConsole/health.jsonl`.
- **Backend** (`LoopbackServer.swift`): 127.0.0.1:9791, GET-only `/health`, `/api/inbox`, `/api/services`;
  anything else 405. `CONSOLE_BACKEND=0` disables it.
- **Home**: Orbit (bot map), service health, approvals count, backend, skill search (~/m3ta-os/skills-library + REA skills).
- Rollback: delete the branch/worktree; remove the two log/ledger files above. No system config is touched.
